使用帮助

从导入到创建一条 IF 支线

按本页从上到下操作即可。创建支线不需要先手动理解全书；程序会自动补齐分叉点之前的阅读记忆，所以分叉越靠后，等待越久。

快速开始

01 导入选择或导入 TXT / EPUB 小说。
02 选章在左栏点开想改写的章节。
03 分叉点“从本章后分叉”，自动带入章节。
04 填写写名称、设定、风格和每章字数。
05 生成点“创建支线并写首章”，等待完成。
推荐路径：用“从本章后分叉”按钮，而不是手动在表单里选章节。它会自动选中你当前阅读的章，并打开创建面板，最不容易选错。

创建前检查

顶部右上角应显示 “我的模型就绪”。如果显示“未配置模型”或“模型未就绪”：

  1. 点顶部“我的模型”。
  2. 选择接口类型，填写 API URL、模型 ID 和你自己的 API Key。
  3. 点“保存并测试”，状态变为“我的模型就绪”后才能生成。

模型未就绪、并发已满或已有任务运行时，“创建支线并写首章”会暂时不可用。

提示：API Key 只保存在本浏览器的 localStorage 中，只发送给你设置的模型接口；不会导出，也不会写入小说数据。公用电脑请用完清除。
跨域要求：页面由浏览器直接请求你设置的模型接口，因此该接口必须允许来自本站的跨域请求（CORS）。接口不支持时，“保存并测试”会失败。
地址要求：其他接口请填写 https:// 地址；浏览器会阻止从 https 页面请求 http 地址。本地 llama.cpp 默认地址为 http://127.0.0.1:8000/v1，需在本机运行，可在“我的模型”中修改。

选择分叉点

分叉点决定“从哪里开始不认原作”。

  1. 在左栏选中要改写的章节。例如“第八章 不准革命”。
  2. 点正文底部的“从本章后分叉”。右侧会自动切到“创建 IF”，并选中这一章。
  3. 看表单下方的提示。它应显示所选章节标题与“之后”，例如：
    “分歧点：第八章 不准革命 之后。该章结束前的事实保留，之后原作全部作废。”

也可以手动在“分叉章节”下拉里选某一章的“之后”，或选“故事开始前（不采用原作剧情）”。

请以章节标题为准。程序内部的“阅读段号”可能因为前言、目录或超长章节拆段而不同于原书章号；界面提示和支线详情都显示标题，不再依赖数字。
支线创建后不能修改分叉点。选错了只能新建一条支线，确认满意后再删除旧支线。

填写创建表单

字段怎么填
支线名称建议带上分叉位置或核心改动，例如“阿Q·玉佩线”“Jekyll·限制资金线”。同名支线可在“全部支线”里按创建时间区分。
分叉章节优先用“从本章后分叉”自动带入；手动选择时认准章节标题和下方提示。
IF 设定 / 转折点写清楚改了什么、人物要做什么、想要什么结果、必须保持的限制。必填。
写作风格可选。例如“保持原作第三人称、冷峻白描，不用现代网络用语”。
每章字数400—4000，默认 1200。这是创作指引，不是精确字数承诺。

分章目标怎么写

如果希望第一章、第二章各有明确任务，用“第1章：”“第2章：”分段。程序会按 IF 章号提取当前章目标，不会把第二章任务提前到第一章。

第1章：阿Q没有去酒店，而是先找小D商量玉佩怎么处理；两人约定共同保管，并留下凭据。
第2章：两人去酒店存玉佩，掌柜只肯按手印出收条；阿Q拿到收条后又担心小D独吞。

不写“第几章”也可以，整段设定会作为当前路线目标，本章需要体现实际进展。

一致性原则：分叉前已成立的事实要一致；分叉后的原作完全忽略，可以创造新人物、动机、事件和结局。不要要求模型参照原作结局，也不要提前完成后面章节的目标。

生成首章

点“创建支线并写首章”后，程序依次执行：

  1. 补齐阅读记忆。如果分叉点之前还没“理解”过，程序会自动阅读并压缩那些章节。
  2. 规划本章行动。根据设定和分叉点规划具体动作、障碍与结果。
  3. 生成正文。顶部输出区实时显示内容，可自动滚动、复制或“放大查看”。

成功时显示“任务完成”，首章保存到新支线。失败时保留“最后完整草稿（未保存）”，可填写具体编辑反馈后点“按反馈修订”。截断、达到 token 上限或 API 错误属于技术失败，不会把半截稿当成正式章节。

没有自动评分。程序只做技术检查，不判断文笔好坏；是否读得舒服由你决定。

阅读与续写

进入右侧“支线”页，可以看到：

  • 开篇位置：原书名、分叉章节标题、该章结尾原文尾段；可展开核对。
  • 已写章节：章号、标题、字数；点击切换阅读。
  • 阅读支线：正文区切到“IF 正文”。
  • 续写一章：按上一章和设定继续写下一章。
  • 导出 TXT：导出当前支线全文。

重新生成末章

“重新生成末章（保留原版）”会新建一条支线，复制原支线除最后一章外的已有章节，再生成替代的最后一章。原支线及其正文保持不变。支线为空时，该按钮用于重试生成首章。

如果只是最后一章不满意，也可用“删除末章”移除它后重新续写。

管理支线

  • 重命名：只改支线名称，不影响正文。
  • 删除末章：只删除最后一条正文及其过期摘要，其他章节保留，可重新续写。
  • 删除支线：删除该支线正文和支线记忆，原书不受影响；不可恢复，会二次确认。
  • 全部支线：列出每条支线的开篇章节、创建时间、已写章数，便于区分同名或多次重生成的支线。

生成中的支线会拒绝改名、删章或删除，避免和数据写入冲突。

删除不可撤销。删除支线前先确认名称和开篇位置；需要保留时先“导出 TXT”。

数据与备份

小说、章节、支线和记忆保存在本浏览器的 IndexedDB 中（数据库名 novel-if），不上传到任何服务器。

  • 其他电脑或其他浏览器看不到这些数据。需要在另一台电脑使用时，先在原电脑“导出数据”，再在那台电脑“导入数据”。
  • 导出数据：下载 novel-if-data.json，包含全部小说、章节、支线和记忆；不包含 API Key。
  • 导入数据：确认后会删除当前浏览器中的全部数据，再用文件内容替换。此操作无法撤销。
  • 清除浏览器的网站数据会删除这些内容；导出的文件是唯一的备份。

常见问题

关闭或刷新页面后任务会怎样？

任务只在当前页面中运行。关闭或刷新页面会中断任务，正在生成的草稿和进度丢失，未完成的章节不会保存。

为什么创建后等待很久？

分叉章节靠后时，程序要先阅读并压缩此前所有章节。已经“理解”过的章节会复用缓存；可以提前点“理解至本章”减少等待。

可以先只理解、不生成吗？

可以。读原文时点“理解至本章”，只建立剧情记忆，不写小说。之后创建支线会更快。

首章不满意怎么办？

点“重新生成末章（保留原版）”，或先“删除末章”再“续写一章”。程序不会自动评分。

为什么按钮是灰的？

模型未就绪、并发已满、已有任务运行，或当前支线正在生成。等任务结束或到“我的模型”检查自己的 Key。

分叉点选错了怎么办？

分叉点不能修改。新建正确支线，确认满意后再删除旧支线。

“第9章后”和“第八章”为什么对不上？

程序会把前言、目录或超长章节拆成阅读段，内部段号不一定等于原书章号。请以章节标题为准。

输出被截断或任务失败怎么办？

这是技术失败，不会保存为正式章节。完整草稿会保留，可填写具体反馈后“按反馈修订”，或重新生成。
