# 小说工作台（Novel IF Workbench）

长篇小说「无矛盾改写 + IF 支线续写」的浏览器工作台。导入原作 → 在某一章之后分叉 →
逐章生成 IF 正文 → 按反馈修订。

纯前端：React + antd 打包成静态文件，所有数据存在浏览器 IndexedDB，模型由使用者自带。

> 课程大作业项目仓库。首次在本地跑之前先读下面的“运行”一节。
> 本文件描述的是**当前代码实际具备的能力**，未实现的部分单列在“已知限制”。

## 已实现的能力

### 1. 导入与切分

- 支持 `.txt` 与 `.epub`，单个文件上限 32 MiB。
- 自动识别文本编码；按 `第N章 / 第N回 / 第N节 / Chapter N` 等标题切章，
  会排除目录、重复标题等明显误判。
- 超长章节按约 12000 字符拆成多个“阅读段”，因此界面里的段号**可能不同于原书章号**，
  以标题为准。

### 2. 阅读与记忆

- “理解至本章 / 理解全书”会逐章生成结构化记忆（事件、人物状态、结束位置）。
- 记忆按章存入本地数据库，并做分层压缩（每 8 章合并一层，最多 4 层）；
  相同的“模型 + 思考强度 + 接口地址”会复用摘要缓存。
- **支持章级断点**：再次执行时，已有记忆的章节直接跳过、不调用模型，从第一处缺失继续。

### 3. 支线创建

- 选择分叉章节（第 1 章到全书末章）、填写 IF 设定、写作风格、每章字数。
- 设定里可以用 `第3章：目标…` 这样的分章目标，生成时会按章取用。
- 暂不支持“故事开始前（第 0 章）”分叉。

### 4. 正文生成

- 流式输出；写作前先做一次简短规划，写完再归档本章记忆。
- 首章生成、继续下一章、重新生成末章（保留原版另开一条支线）。
- 生成期间锁定该支线的改名、删除、删章，避免状态冲突。
- 失败、截断、取消都**不会把半成品写进正文表**；已保存章节不受影响。

### 5. 草稿保护

- 最近任务的完整草稿与状态存在 `sessionStorage`（同标签页刷新可恢复）。
- 刷新后未完成任务标记为“已中断”，**不会自动重发请求**；草稿可复制，也可按反馈修订。
- 不保存 API Key、模型配置、流式半成品或思考内容；关闭面板即清除。

### 6. 数据与备份

- IndexedDB 共 8 张表：书籍、原文章节、原作记忆、支线、IF 章节、IF 记忆、
  记忆视图缓存、摘要缓存。
- “导出数据”生成一个 JSON（**不含 API Key**）；导入会用文件**整体替换**现有数据。

### 7. 模型接入

- OpenAI 兼容接口，内置 DeepSeek、SiliconFlow、本地 llama.cpp、自定义四类预设。
- SSE 流式解析；支持思考强度（none/low/medium/high）。
- 密钥只存本机 `localStorage`，且**只在同一协议 + 主机 + 端口内复用**；
  更换接口地址后需要重新填写。
- 接口必须允许浏览器跨域（CORS）。

### 8. 任务系统

- 同一时间只跑一个任务；任务面板显示阶段、进度、流式输出。
- 可取消；取消后已完成的部分（如已理解章节）保留。
- 结果状态分为完成 / 失败 / 已取消，失败会显示原因。

## 使用方法

### 运行

```bash
npm ci          # 安装锁定依赖
npm run build   # 打包到 static/app.js
npm test        # Node 内置测试运行器
```

打开页面：把 `static/` 作为站点根目录提供即可，例如

```bash
python3 -m http.server 8100 --bind 127.0.0.1 --directory static
# 浏览器打开 http://127.0.0.1:8100/
```

> 页面里 `app.js`、`app.css` 用的是根路径，所以必须以 `static/` 为根，不能直接双击 `index.html`。

首次使用：点“我的模型”填接口地址、模型 ID、API Key，测试通过后导入小说。

## 代码结构

| 文件 | 职责 |
|---|---|
| `src/engine.js` | 任务编排、支线/章节读写、生成与修订流程 |
| `src/memory.js` | 分块摘要、分层记忆、证据检索、记忆视图 |
| `src/model.js` | 模型请求：配置校验、SSE 解析、思考预算、上下文预算 |
| `src/text.js` | TXT/EPUB 解析与切章、超长章节拆段 |
| `src/store.js` | IndexedDB 建表、事务、整体导入导出 |
| `src/goals.js` | 从设定里解析 `第N章：…` 分章目标 |
| `src/credentials.js` | 密钥归属判断（同源复用规则） |
| `src/validation.js` | 创建支线前的章号与字数校验 |
| `src/jobs.js` | 任务与支线的归属判断 |
| `src/job-recovery.js` | 最近任务的快照保存/恢复 |
| `frontend/main.jsx` | 单页界面（React + antd） |
| `static/` | 打包产物、入口页、使用帮助 |

## 测试

- `npm test`：单元与协议测试（当前 34 项），覆盖密钥规则、输入校验、任务归属、
  草稿恢复、SSE 分块/截断/取消/错误等。
- `node tests/browser-integration.mjs`：真实浏览器 + 真实 IndexedDB 的集成验证，
  使用合成小说、合成模型响应和独立临时 Chrome 配置目录，不联网、不调用真实模型。
  需要本机 Chrome，可用 `CHROME_PATH` 指定路径；**未加入 `npm test`**。

## 已知限制

- **正文生成没有断点续写**：失败或取消后只能整章重写，不会从半句接上。
- **理解/记忆是章级断点**，不是句中续跑；每章失败会重试 2 次。
- 网络错误目前和“输出被截断”共用同一套重试提示，容易误判为“内容太长”。
- 流式请求只有 30 分钟空闲超时，没有首包超时，连接卡死时反应较慢。
- 没有跨标签页并发锁：两个窗口同时操作同一支线不做冲突保护。
- 尚未实现独立的一致性检查：目前只在生成时通过提示词约束，没有冲突列表与证据展示。
- 没有结构化事实库、版本谱系或自动修复。
- 后端能力、账户体系、多人协作均未实现；数据只在本浏览器内。
- 仅支持 TXT/EPUB，不支持 MOBI/AZW3/带 DRM 的文件。

## 常见问题

**按钮是灰的？**
模型未就绪、并发已满，或当前窗口已有任务，都会禁用生成类按钮。

**提示“无法调用模型 API：Failed to fetch”？**
多半是 CORS 被拒、页面与接口的协议不匹配（https 页面请求 http 地址），
或本机转发器没有运行。先在浏览器里打开接口地址确认可达。

**刷新后任务不见了？**
未完成任务会显示为“已中断”，草稿保留但不自动继续；需要手动确认再重试。

**导入数据会怎样？**
会删除当前浏览器里的全部小说、章节、支线和记忆，然后整体替换，无法撤销。

更细的界面操作说明见页面内的“帮助”（`static/help.html`）。
